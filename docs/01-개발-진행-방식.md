# 개발이 시작되면 어떻게 되는가

기획서를 넘긴 시점부터 플레이 가능한 게임이 나올 때까지의 흐름.

---

## 한눈에

```
 [사용자]                    [AI]                      [GameForge 툴]
    │
 기획서 ppt/txt  ────────▶  읽고 스펙으로 옮김
 Specs/inbox/ 에 넣기            │
                                ▼
                          Specs/<name>.json
                                │
                                ├──────────────▶  validate   기획서 점검
                                │                              │
                                │                   ┌──────────┴──────────┐
                                │                   │ 오류 있으면 여기서 멈춤 │
                                │                   └──────────┬──────────┘
                                │                              ▼
                                ├──────────────▶  gen        코드·씬·UI·시뮬 생성
                                │                              │
                                ▼                              ▼
                          dotnet build              Assets/Games/<Name>/
                          컴파일 확인                 Sim/<Name>/
                                │
                                ├──────────────▶  --tune     수만 판 돌려 수치 탐색
                                │                              │
                                ├──────────────▶  apply      찾은 수치를 기획서에 반영
                                │                              │
                                └──────────────▶  gen        재생성
                                                               │
 유니티에서 Play  ◀──────────────────────────────────────────────┘
    │
 "점프가 굼떠" 같은 피드백  ────▶  스펙 수정 → 재생성
```

---

## 1단계 — 기획서 전달

`Specs/inbox/` 에 파일을 넣는다. **ppt / pptx / txt / md / 스크린샷** 무엇이든 된다.

기획서에 아래가 있으면 자동화가 훨씬 정확해진다. 없어도 진행은 되고, 빠진 값은 장르 기본값으로 채운 뒤
"이렇게 가정했습니다" 하고 알려준다.

- **장르** (또는 "○○ 같은 게임" 이라는 참고작)
- **자원 종류** (골드/보석/에너지 …)
- **성장 대상 목록** (시설, 타워, 유닛, 무기 …) 과 대략의 능력치
- **목표 진행 속도** ("1일차에 어디까지", "한 판 몇 분")

문서 한 장짜리여도 시작할 수 있다. 부족한 부분은 질문으로 채운다.

---

## 2단계 — 기획서 → 스펙 (여기만 사람/AI 판단)

AI 가 문서를 읽고 `Specs/<name>.json` 을 만든다. 이 JSON 이 **단일 진실원본**이다.
이후 나오는 모든 코드·데이터·화면은 이 파일에서 파생된다.

쓸 수 있는 필드는 `gameforge schema` 로 확인한다.

```bash
dotnet Tools/GameForge/bin/Debug/net9.0/gameforge.dll schema
```

**자동화가 안 되는 유일한 단계다.** 문서의 서술을 수치로 옮기는 판단이 들어가기 때문이다.
대신 그 결과를 다음 단계에서 기계가 검사한다.

---

## 3단계 — 점검 (validate)

```bash
gameforge validate Specs/mygame.json
```

빠진 필드, 존재하지 않는 자원 id 참조, 말이 안 되는 수치를 잡는다. 예를 들면:

```
[오류] match3: 목표 점수 3000 이 20수로 낼 수 있는 낙관적 상한 1800 을 넘습니다.
       1스테이지부터 클리어가 불가능합니다.
[경고] enemies 'brute': armor 6 가 최저 타워 공격력 8 의 절반 이상입니다.
       초반에 그 타워로는 딜이 거의 안 들어갑니다.
```

**오류가 하나라도 있으면 생성이 중단된다.** 컴파일 에러로 만나는 것보다 여기서 걸리는 편이 훨씬 싸다.

---

## 4단계 — 생성 (gen)

```bash
gameforge gen Specs/mygame.json
```

한 번에 다음이 전부 나온다.

| 나오는 것 | 내용 |
|---|---|
| `Assets/Games/<Name>/Core/` | 게임 로직 + 밸런스 테이블 (순수 C#) |
| `Assets/Games/<Name>/Unity/` | 고정 스텝 러너, HUD, 2D 월드 뷰, 플레이스홀더 아트 |
| `Assets/Games/<Name>/Editor/` | 씬 생성 메뉴, 리소스·설정 점검 메뉴 |
| `Assets/Games/<Name>/Resources/` | **리소스 폴더 4종이 자동으로 만들어진다** (Icons/Sprites/Backgrounds/Audio) |
| `Assets/Games/<Name>/리소스-넣는-법.md` | 그 게임에 맞춘 리소스 안내 문서 |
| `Sim/<Name>/` | 밸런스 시뮬레이터 |

**프리팹을 만들거나 인스펙터에 드래그로 참조를 꽂는 작업이 없다.** UI 는 실행 시점에 코드가 만든다.
씬에 `GameRunner` 컴포넌트 하나만 있으면 게임이 성립한다.

---

## 5단계 — 컴파일 확인

유니티를 켜지 않고 확인한다. (사용자가 에디터를 열어두면 배치모드가 막히기 때문)

```bash
dotnet build Sim/<Name>/<Name>.Sim.csproj        # 게임 로직
dotnet build Tools/UnityCheck/UnityCheck.csproj  # 유니티 레이어
```

AI 가 이 루프를 스스로 돈다. 에러가 나면 고치고 다시 돌린다.
사용자가 유니티를 열어 에러를 확인하고 알려줄 필요가 없다.

---

## 6단계 — 밸런스 (여기가 이 도구의 핵심)

```bash
dotnet run --project Sim/<Name>/<Name>.Sim.csproj
```

가상 플레이어가 게임을 대신 플레이한 결과를 보고한다.

```
-- 스테이지별 도달률 --
  스테이지   5 : 100.0%  ####################
  스테이지  10 :  66.7%  #############.......
  스테이지  15 :   0.0%  ....................

-- 진단 --
  [벽] 스테이지 11 부터 절반 이상이 진행하지 못함
```

수치를 자동으로 찾게 하려면:

```bash
dotnet run --project Sim/<Name>/<Name>.Sim.csproj -- --tune
```

두 축을 격자로 훑어 목표에 가장 가까운 조합을 찾아준다.

```
  수 제한 / 목표점수 증가율  1.04     1.06     1.08     1.10
      22수                 18.2단/82%  14.1단/76%  10.1단/71%   8.0단/64%
      26수                 24.0단/88%  19.3단/83%  15.2단/78%  12.1단/72%

추천 조합: moves = 26, targetGrowth = 1.08
```

찾은 값을 기획서에 되먹이고 재생성한다.

```bash
gameforge apply Specs/mygame.json --moves 26 --target-growth 1.08
gameforge gen Specs/mygame.json
```

**사람이 30일을 플레이해 보지 않아도 진행 곡선이 잡힌다.** 이 단계가 자동화의 실질적인 이득이다.

---

## 7단계 — 유니티에서 확인

```
메뉴 > GameForge > <게임 이름> > 씬 생성 및 열기 (타이틀부터)
Play
```

씬은 **타이틀 씬 → 게임 씬** 2씬 구성으로 생성되고, 둘 다 빌드 세팅에 자동 등록된다.
타이틀에서 화면을 누르면 게임 씬으로 넘어간다. 게임 씬만 바로 보려면 "게임 씬 열기" 메뉴.

여기서 처음으로 사람 눈이 필요하다. 보고 나서 피드백을 말로 주면 된다.

- "초반이 너무 빨라" → 기획서 수치 조정 → 재생성
- "합성 연출이 밋밋해" → 이미터 수정 → 재생성
- "이 유닛이 쓸모없어" → 시뮬로 확인 후 능력치 조정

---

## 8단계 — 아트 교체

기본은 색 플레이스홀더다. 폴더는 4단계에서 이미 만들어져 있다.

```
Assets/Games/<Name>/Resources/
├─ Icons/         버튼 아이콘
├─ Sprites/       월드 스프라이트 (판·유닛·적)
├─ Backgrounds/   배경
└─ Audio/         사운드
```

1. 이미지를 `Icons/` 또는 `Sprites/` 에 넣는다
2. 기획서의 해당 항목 `icon` 에 **파일명만** 적는다 (폴더·확장자 없이)
3. 재생성

`메뉴 > GameForge > <게임> > 리소스 점검` 으로 빠진 이미지를 확인할 수 있다.
빠져 있어도 플레이스홀더로 계속 굴러가므로, **아트가 없어도 게임을 먼저 완성**할 수 있다.

자세한 규칙은 [03-리소스-넣는-법.md](03-리소스-넣는-법.md).

## 사용자가 실제로 하는 일

| 단계 | 사람 |
|---|---|
| 1 기획서 전달 | ○ |
| 2 스펙 변환 | AI |
| 3 점검 | 툴 |
| 4 생성 | 툴 |
| 5 컴파일 확인 | AI |
| 6 밸런스 | 툴 + AI |
| 7 Play 확인 | ○ |
| 8 아트 | ○ (이미지 준비) |

정리하면 **기획서를 쓰고, 가끔 Play 해 보고, 피드백 한 줄 주는 것** 세 가지다.

---

## 자동화되지 않는 것

솔직하게 적어둔다.

- **아트 리소스 제작** — 이미지·사운드·모델은 못 만든다. 플레이스홀더로 게임을 완성한 뒤 교체하는 방식
- **게임 필과 연출** — 타격감, 연출 타이밍은 보고 말해줘야 조정된다
- **스토어 등록·심사·광고 SDK 키** — 계정 작업
- **실시간 멀티플레이** — 지금 6종은 전부 싱글. 결정론 구조는 깔려 있어 나중에 확장은 가능하지만, 서버·계정·치트방지는 별개의 작업이다
